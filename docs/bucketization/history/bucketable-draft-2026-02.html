Bucketable

Bucketable is a persistent, bucket-indexed sorting interface optimized for interactive user interfaces such as file explorers, asset browsers, IDE file lists, and similar systems where the same dataset is re-sorted repeatedly by a small set of known attributes.

Subtitle:
Bucketable: a persistent bucket-indexed sorting interface for interactive UIs

1. Motivation

Traditional comparison-based sorting algorithms (std::sort, qsort) recompute ordering from scratch every time the user changes a sort key. In interactive systems, this leads to repeated O(n log n) work on essentially static datasets.

Bucketable reframes sorting as a persistent interface problem rather than a transient algorithmic one. By pre-bucketing items according to sortable attributes, it enables instant sort switching with predictable performance.

2. Core Concept

Each sortable attribute maps items into a fixed number of buckets (typically 256). For each attribute, Bucketable builds and stores:

  • A bucket histogram
  • Prefix-sum offsets
  • A stable bucket-ordered item array

Switching sort order is reduced to selecting a precomputed ordering, making UI sort operations effectively constant time.

3. Why 8-Bit Buckets

  • 256 counters fit comfortably in L1 cache
  • Prefix sums are trivial and fast
  • Good balance between resolution and overhead
  • Natural fit for SIMD and parallelization

Other bucket widths are possible, but 8-bit buckets are the recommended default.

4. Attribute Bucketing Strategies

4.1 Dates and Timestamps

Dates are normalized to a monotonic integer representation (e.g. Unix timestamp). Bucketable uses dataset-local ranges rather than fixed global epochs.

Range definition:

  • min_date = minimum timestamp in dataset
  • max_date = maximum timestamp in dataset

Bucket mapping:

bucket = (date - min_date) * 255 / (max_date - min_date)

If min_date == max_date, all items map to bucket 0.

4.2 Numeric Attributes

Numeric attributes (file size, counters, IDs) use the same linear normalization strategy as dates.

4.3 Strings

Strings use a two-phase strategy: coarse radix-style bucketing followed by locale-aware ordering within buckets.

struct bucketable_string_key {
    uint8_t primary;
    uint8_t secondary; /* optional */
    uint16_t spill;
};
Note: Bucketable does not replace locale-aware collation.

5. Statistics vs Radix Strategies

Radix-style bucketing is the default. Quantile/statistics-based bucketing is optional and opt-in.

6. Multi-Key Sorting

Bucketable supports persistent, radix-like multi-key sorting.

7. Reference C Interface

typedef uint8_t (*bucket_fn)(const void *item);

typedef struct {
    bucket_fn bucket;
    const char *name;
} bucketable_key_t;

typedef struct {
    void   **items;
    size_t   count;
    size_t   bucket_offsets[257];
} bucketable_index_t;

8. Invalidation Model

Indices are rebuilt only when data or attribute semantics change.

9. Implementation Language

The core library is implemented in C for ABI stability and maximum interoperability. Optional C++ wrappers may be provided.

10. Summary

Pay once, reuse until invalidated.
